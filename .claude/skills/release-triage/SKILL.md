# Triaging a failed OpenRehearse pipeline run

Advisory only. Report the cause and the fix — do not re-run builds yourself. The EAS
free tier allows 15 Android builds per month and a speculative re-run spends one.

## Steps

1. **Locate the run.**

   ```bash
   gh run list --workflow=release.yml --limit 5
   gh run list --workflow=ci.yml --limit 5
   gh run view <run-id> --log-failed
   ```

2. **If the failing step is `Build on EAS and wait`**, the real logs are on EAS, not in
   the Actions log. Get the build page:

   ```bash
   cd client && npx eas-cli build:list --platform android --limit 3
   npx eas-cli build:view <build-id>
   ```

3. **Match against the known causes below before theorising.**

4. **Report**: the failing job and step, the actual root cause, and the specific fix.
   State plainly if you cannot determine the cause from the logs rather than guessing.

## Known causes

| Symptom | Cause | Fix |
|---|---|---|
| `quality` fails on `Cannot find module '@score-web/html'` | `client/src/score-web/html.ts` is generated by `postinstall`, not committed — the bundler step failed or install ran with `--ignore-scripts` | `cd client && npm run build:score-web` and read its output; the real error is in the esbuild run |
| `pr-title` fails | PR title is not a Conventional Commit, or uses a type outside `commitlint.config.mjs` | Rename the PR; squash merge means the title becomes the commit on main |
| Nothing happened after merging to `main` | Not a failure. `release.yml` is dispatch-only — merging ships nothing | Cut the release deliberately with the `release` skill |
| `Derive the app version from the tag` fails | The tag is not a plain `vX.Y.Z`, or minor/patch exceeded 99 | Re-tag correctly; the `versionCode` encoding cannot represent it |
| EAS build fails at auth | `EXPO_TOKEN` missing or revoked | New access token at expo.dev → Account → Access tokens |
| EAS build rejected on quota | The 15 builds/month free-tier cap | Wait for the reset or upgrade; do not retry blindly |
| Android rejects the APK on install | `versionCode` did not increase | `release.yml` derives it from the tag as `major*10000 + minor*100 + patch`; check the new tag really is higher than the installed build's |
| Release created but no APK attached | `build-apk` failed after the release was already made | Diagnose first, then re-attach without re-releasing via the `release` skill's rebuild mode (`/release <tag>`) |

## Rules

- Do not trigger `workflow_dispatch` or any EAS build without the user asking.
- Do not edit or delete a published release.
- If the failure is in `quality`, treat it as an ordinary lint/type/test failure and
  reproduce locally with `cd client && npm run ci` rather than reading CI logs further.
